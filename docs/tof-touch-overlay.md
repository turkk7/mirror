# طبقة لمس افتراضية بحسّاسَي ToF (VL53L1X) — مواصفة تنفيذ

> مستند تصميم جاهز للتطبيق عند وصول القطع. الهدف: تحويل شاشة TV عادية (غير لمسية) خلف
> المرآة ذات الاتجاهين إلى سطح "لمس" أحادي النقطة، بدون تغيير منطق أزرار الواجهة.

## ١. الفكرة

حسّاسان VL53L1X مركّبان في **إطار** البوث وموجَّهان بمحاذاة سطح المرآة (grazing، موازٍ
للزجاج بـ١–٢ مم فوقه):

- **الحسّاس العمودي (V)**: أعلى منتصف الإطار، يصوّب للأسفل. مسافته للإصبع = الإحداثي **Y**.
- **الحسّاس الأفقي (H)**: منتصف جانب الإطار، يصوّب أفقياً. مسافته للإصبع = الإحداثي **X**.

عند دخول إصبع واحد إلى مستوى السطح، يلتقطه الحسّاسان في آنٍ واحد؛ **تقاطع (X,Y)** هو نقطة
اللمس. نولّد عندها نقرة صناعية في المتصفّح، فتستقبلها أي عناصر الواجهة الموجودة طبيعياً.

هذا **تثليث بمحورين** (triangulation)، وليس شاشة لمس حقيقية. اقرأ قسم «القيود» قبل أي وعد.

```
        V (down)
      ┌──┬────────────┐
      │  ▼            │
   H →│  · (X,Y)      │   ·  = الإصبع عند تقاطع الشعاعين
      │               │   X = مسافة H   |   Y = مسافة V
      └───────────────┘
```

لأن الحسّاسات في الإطار وتمسح السطح فقط (لا تنظر عبر فيلم المرآة)، **لا توجد مشكلة مرور
أشعة 940nm عبر المرآة** — المسار البصري مكشوف. (قرار التركيب هذا هو ما ألغى المخاطرة.)

## ٢. القيود (اقرأها أولاً — تُدار بالتصميم لا بالتمنّي)

1. **لمسة واحدة فقط.** الحسّاس يُرجع أقرب جسم؛ إصبعان = نتيجة ملتبسة. مقبول للبوث (نقرة مفردة).
2. **دقّة خشنة.** عبر شاشة ~١م وبهندسة grazing، توقّع دقة بالسنتيمترات لا المليمترات —
   كافية لأزرار كبيرة، غير كافية لمؤشّر دقيق. صمّم الأزرار كبيرة ومتباعدة.
3. **تداخل الساعد على محور X.** مجال رؤية الحسّاس واسع (~27°)؛ قد يرى الساعد قبل طرف الإصبع.
   التخفيف: تضييق الـROI إلى ~15° عبر مصفوفة SPAD، ومحاذاة grazing دقيقة، وأزرار متباعدة.
4. **حساسية الميكانيكا عالية جداً.** انحراف ملّيمترات عن موازاة الزجاج → إمّا يلمس الزجاج
   (تشويش دائم) أو يفوّت الإصبع. يلزم **حامل قابل للمعايرة** + **معايرة crosstalk** (مدعومة في مكتبة VL53L1X).
5. **زمن استجابة** = دورة القياس. استخدم timing budget قصير (~٢٠–٣٣ مل‌ث) لـ٣٠–٥٠Hz.
6. **وضع المسافة**: `Short` أدق مع الإضاءة المحيطة وحتى ~١.٣م (يناسب شاشة طولية ~١م)؛
   `Long` حتى ٤م لكنه أضعف مع الضوء. البوث مظلم أصلاً — وهذا في صالحنا. ابدأ بـ`Short`.

## ٣. العتاد والتوصيل

| العنصر | التفصيل |
|---|---|
| المتحكّم | ESP32-S3 (نفس القطعة؛ يمكنها خدمة زر التصوير والطبقة اللمسية معاً على نفس كيبل USB). |
| الحسّاسان | 2× VL53L1X على ناقل I2C مشترك. |
| XSHUT | **إلزامي**: الاثنان يبدآن بالعنوان 0x29. نوصّل XSHUT لكل حسّاس بـGPIO، نوقظهما بالتتابع، ونعيد تعيين عنوان الثاني (مثلاً 0x2A) عند الإقلاع. |
| I2C | SDA/SCL لأي زوج GPIO على S3 (مثلاً GPIO8/GPIO9) + مقاومات سحب 4.7kΩ. |
| GPIO1 (اختياري) | خطّا المقاطعة (interrupt) لكل حسّاس لتقليل استطلاع I2C. |
| الوصلة للكيوسك | USB → **Web Serial** إلى Chromium (115200). كيبل واحد. |

تركيب فيزيائي: كلا الحسّاسين في الإطار، عدسة الحسّاس على بُعد ١–٢ مم فوق مستوى الزجاج
وموازية له تماماً. V أعلى المنتصف ينظر للأسفل؛ H منتصف جانب ينظر عرضياً. حامل قابل للضبط
الدقيق ضروري.

## ٤. تقسيم المسؤوليات (مهم للمعايرة)

- **الطرف الصلب (ESP32-S3)**: يقرأ المسافتين الخام فقط + علم صلاحية كل قياس، ويرسلهما عبر
  السيريال بوتيرة ثابتة. **لا يحسب الإحداثيات ولا المعايرة.**
- **الواجهة (JS)**: تملك المعايرة (تحويل المسافة → بكسل/نسبة)، ومنطق كشف اللمسة (التزامن +
  إزالة الارتداد)، وحقن أحداث المؤشّر.

السبب: نعاير ونضبط العتبات من المتصفّح **دون إعادة فلاش** للمتحكّم في كل تجربة.

## ٥. بروتوكول السيريال (ESP32 → JS)

أسطر نصّية CSV، سطر لكل إطار قياس:

```
R,<dv_mm>,<dh_mm>,<vv>,<vh>
```
- `dv_mm`,`dh_mm`: المسافة الخام بالمليمتر لكل حسّاس.
- `vv`,`vh`: صلاحية القياس (0/1) من حالة التصنيف في VL53L1X (RangeStatus).

سطر حالة دوري (نبضة قلب): `S,ready` / `S,err,<code>`. (وإن أضفنا زر التصوير لاحقاً على نفس
القطعة: سطر مستقل `B,press`.)

## ٦. منطق اللمس (في JS)

1. **خطّ الأساس (baseline)**: عند الإقلاع وبلا إصبع، سجّل `dv0`,`dh0` (المسافة إلى الجدار/أقصى المدى).
2. **كشف الدخول**: يُعتبر محور «مشغولاً» إذا `d < d0 − margin` و`valid==1` ضمن المدى.
3. **لمسة صالحة**: يجب أن يكون **المحوران مشغولَين معاً** خلال نافذة زمنية `Δt` (مثلاً 60مل‌ث).
   مشغول واحد فقط (يد عابرة أمام حسّاس) = **لا نقرة** (رفض طبيعي للإيجابيات الكاذبة).
4. **إزالة ارتداد**: `N` إطارات متتالية (مثلاً 2–3) قبل اعتماد down/up.
5. **التحويل (المعايرة)**: خريطة خطّية/أفاينية من `(dv,dh)` → `(nx,ny)` بنسبة 0..1.
   تُحسب من معايرة نقاط معلومة (الأركان + المركز).
6. **الأحداث**: `down` عند تحقّق الشرط، `move` أثناء البقاء، `up` عند تحرّر أي محور.

## ٧. حقن النقرة في الواجهة

وحدة جديدة `frontend/js/touch-serial.js` تفتح `navigator.serial`، وتقرأ الأسطر، وبعد حساب
`(nx,ny)` تحوّلها لبكسل وتُطلق أحداث المؤشّر على العنصر الأعلى عند النقطة:

```js
function synthClick(nx, ny) {
  const x = Math.round(nx * window.innerWidth);
  const y = Math.round(ny * window.innerHeight);
  const el = document.elementFromPoint(x, y);
  if (!el) return;
  const base = { clientX: x, clientY: y, bubbles: true, cancelable: true,
                 pointerType: "touch", isPrimary: true };
  el.dispatchEvent(new PointerEvent("pointerdown", base)); // شاشة الانتظار تستمع لهذا
  el.dispatchEvent(new PointerEvent("pointerup", base));
  el.dispatchEvent(new MouseEvent("click", base));          // الأزرار تستمع لهذا
}
```

**لماذا بلا تعديل منطق الأزرار؟** الواجهة الحالية تستمع لـ`pointerdown` على شاشة الانتظار
(`main.js:27`) ولـ`click` على الأزرار (`flow.js:37`, `btn-home`, و`chooser-options`).
النقرة الصناعية عند (X,Y) تمرّ عبر `elementFromPoint` فتصيب الزر الصحيح طبيعياً. النقر خارج
أي زر = لا شيء. هذا يحقّق مطلبك: **نقرة عند التقاطع، لا اختيار زر مُبرمَج مسبقاً.**

> تنبيه خصوصية/UX: لا نعرض مؤشّراً أو أي بيانات تشغيلية للضيف. النقرة صامتة بصرياً عدا
> تأثير الزر نفسه (قاعدة «الضيف لا يرى بيانات تشغيلية» محمَّلة في `flow.js`).

## ٨. إذن Web Serial في وضع الكيوسك

`navigator.serial` يتطلب عادةً إيماءة مستخدم + اختيار منفذ. في الكيوسك نمنحه تلقائياً عبر
سياسة Chromium:
- `SerialAllowAllPortsForUrls` (أو `DefaultSerialGuardSetting`) لمصدر `http://localhost:8000`.
- بديل مؤقت للتجربة: منح يدوي لمرة واحدة من قائمة المنفذ.

يُضاف المنح إلى تشغيل الكيوسك في `~/mirror/kiosk.sh` على البوث (راجع CLAUDE.md «Live booth»).

## ٩. إجراء التشغيل عند وصول القطع (bring-up)

1. فلاش ESP32-S3 ببرنامج القراءة الخام + إعادة تعيين عنوان XSHUT للحسّاس الثاني.
2. تثبيت الحسّاسين في الإطار بمحاذاة grazing؛ معايرة crosstalk (بلا هدف، ثم هدف معلوم).
3. **اختبار مرور بصري**: تأكيد أن الحسّاس يقرأ إصبعاً يلمس الزجاج ولا يقرأ الزجاج نفسه
   (اضبط ارتفاع ١–٢ مم حتى يختفي القياس الثابت القريب).
4. تسجيل خطّ الأساس وعتبات الدخول من أداة معايرة في المتصفّح (نضيف وضع يعرض `dv,dh` الخام).
5. معايرة النقاط: المس الأركان الأربعة + المركز، احسب الخريطة الأفاينية، خزّنها.
6. ضبط `Δt`, `margin`, `N` حتى تطابق النقرة الموقع المقصود.

## ١١. قائمة القطع

- 2× VL53L1X (المتوفّرة، مدى 4م). **ملاحظة ميدانية:** ملصق الموديول قد يقرأ «VL53L0»
  وهو مضلّل — الشريحة VL53L1X فعلاً (أكّدناها بنجاح إقلاع مكتبة SparkFun VL53L1X).
- 1× ESP32-S3 (المتوفّرة؛ النسخة المستخدمة ESP32-S3-N16R8، جسر سيريال CH343).
- أسلاك XSHUT/INT، كيبل USB، حامل تركيب قابل للضبط في الإطار.
- **لا حاجة لمقاومات سحب خارجية** — ألواح VL53L1X الجاهزة فيها سحب I2C مدمج (~10kΩ)،
  والاثنان على التوازي (~5kΩ) سليم. (التصميم الأصلي ذكر 4.7kΩ؛ أُلغيت بعد التحقّق.)

## ١٢. سجلّ التشغيل الفعلي (bring-up log)

### ما أُنجز (2026-10-23 → 2026-10-24)

**بنية `firmware/` (PlatformIO داخل الريبو):**
- `platformio.ini` — لوح `esp32-s3-devkitc-1`، إطار Arduino، مكتبة
  `sparkfun/SparkFun VL53L1X`. بيئات مفصولة بـ`build_src_filter`:
  - `esp32-s3` → `src/main.cpp` (البرنامج الكامل: حسّاسان، بروتوكول `R,dv,dh,vv,vh`).
  - `test-single` → `src/single_sensor.cpp` (حسّاس واحد، خرج `d=<mm> valid=<0/1>`).
  - `scan` → `src/i2c_scan.cpp` (ماسح I2C، يجرّب 8/9 و9/8 تلقائياً).
  - `diag` → `src/pin_diag.cpp` (مسح أطراف بلا I2C: سحب داخلي للأسفل + قراءة HIGH).
- `README.md` — توصيل + فلاش + bring-up + أوامر معايرة.
- `sensor-test.html` — صفحة Web Serial مستقلّة تعرض المسافة برقم كبير مباشر
  (تُفتح في Chrome عبر `file://`؛ تقرأ صيغتَي `d=..mm` و`R,..`).

**واجهة الكيوسك:** `frontend/js/touch-serial.js` + استيراد سطر واحد في `main.js`.

### الأدوات (على ماك المطوّر)
- PlatformIO عبر `pipx install platformio` → `~/.local/bin/pio`. بايثون المعزول فيه
  pyserial: `~/.local/pipx/venvs/platformio/bin/python` (مفيد لقراءة السيريال بسكربت).
- أوامر: `pio run -e <env> -t upload` للفلاش، و`pio device list` لرؤية المنفذ.

### حقائق عتاد مثبّتة
- **المنفذ:** جسر CH343 (VID `1A86:55D3`) يظهر كـ`/dev/cu.usbmodem5CE51235641`
  (الاسم قد يتغيّر عند إعادة التوصيل — اكتشفه ديناميكياً). هذا منفذ UART بسيط.
- **`Serial` على UART0 الافتراضي** → يصل الجسر مباشرة. **لا** تضع
  `ARDUINO_USB_CDC_ON_BOOT`/`ARDUINO_USB_MODE` (تلك للمنفذ الأصلي USB-JTAG، لا للجسر).
- **الأطراف:** I2C = GPIO8 (SDA) / GPIO9 (SCL)؛ XSHUT: V=GPIO4، H=GPIO5؛
  عنوان الحسّاس العمودي بعد إعادة التعيين = `0x2A`، والأفقي يبقى `0x29`.
- **`setROI` في مكتبة SparkFun تأخذ 3 وسائط**: `setROI(x, y, opticalCenter)` والمركز
  الافتراضي `199`. الحد الأقصى للمجال = **27° (16×16)**؛ للّمس نضيّقه لـ**~15° (4×4)**.

### دروس مستفادة (مهمة)
1. **الحم دبابيس الهيدر أولاً.** أطول عقبة كانت أن دبابيس الموديول **غير ملحومة** —
   موصّل الدوبونت يمسك الدبوس لكن الدبوس غير متّصل بلوحة الحسّاس، فلا طاقة ولا I2C رغم
   سلامة كل الأسلاك. مع الموديولات الرخيصة: تأكّد من اللحام قبل أي تشخيص برمجي.
2. **تسلسل التشخيص الفعّال:** `diag` (طاقة/تلامس) → `scan` (ظهور العنوان) →
   `test-single` (قراءة فعلية). لا تبدأ من I2C قبل تأكيد الطاقة.
3. **المنفذ يفتحه برنامج واحد فقط** — أغلق `sensor-test.html` في المتصفّح قبل أي
   فلاش/قراءة من الطرفية، والعكس (خطأ `Resource busy`).

### الحالة والخطوة التالية
- ✅ الحسّاس الأول يقرأ مسافات صحيحة على الطاولة (مثلاً ~850مم، `valid=1`).

## ١٣. تحوّل الخطة إلى حسّاس واحد (2026-10-24)

بقرار المستخدم، أُلغي التثليث بمحورين. **حسّاس VL53L1X واحد في أسفل إطار المرآة** يصوّب
للأعلى بمحاذاة سطح الشاشة. نموذج التفاعل المختار: **موضع رأسي (محور Y)** — المسافة تتحوّل
إلى إحداثي Y والنقرة عند **منتصف العرض** (nx=0.5)، فتصيب الأزرار العريضة المرصوفة عمودياً.
(حسّاس واحد لا يعطي X؛ لذا الأزرار العمودية — كقائمة المؤقّت — هي النمط المناسب.)

**سبب التحوّل:** محاولة لحام الحسّاس الثاني على الوصلات المشتركة سبّبت قصراً على 3V3 أطفأ
ESP بالكامل (المنفذ يظهر لكن الشريحة لا تردّ: `Failed to connect ... No serial data received`).
إزالة أسلاك الثاني أعادتها. **درس: جسر CH343 يظهر كمنفذ حتى لو ESP ميّتة — «No serial data»
= قصر/brownout، افصل USB وافحص 3V3↔GND بالملتيميتر.**

**التوصيل النهائي (حسّاس واحد):** VIN→3V3 · GND→GND · SDA→GPIO8 · SCL→GPIO9 ·
**XSHUT→3V3** (مربوط بالعتاد، يُبقيه مشغّلاً؛ الفيرموير لا يقوده) · العنوان 0x29.

**الفيرموير:** `firmware/src/single_main.cpp` (بيئة `esp32-s3`؛ كود الحسّاسَين القديم محفوظ
في بيئة `dual`). البروتوكول المبسّط: `R,<d_mm>,<v>` + `S,ready`/`S,err`. ✅ مُختبَر على الماك:
إقلاع ناجح، بثّ ~40Hz، `valid=1`.

**الواجهة:** `frontend/js/touch-serial.js` أُعيدت كتابتها للمحور الواحد — خطّ أساس + كشف
دخول (d < baseline − margin) + debounce، معايرة نقطتين (أعلى/أسفل) في localStorage
`qamra.touchcal.single`، نقرة عند (0.5, ny) عبر `elementFromPoint`. النقرة تُحقن عند **آخر
موضع صالح** قبل انسحاب اليد (لأنّ الانسحاب يُفقد اليد فجأة لا تدريجياً).

**إجراء المعايرة على البوث (من `?cal=1` + console):**
1. بلا يد، اترك خطّ الأساس يُلتقط (أو `qamraTouch.rebaseline()`).
2. ضع اليد عند أعلى منطقة الأزرار ثم `qamraTouch.markTop()`.
3. ضع اليد عند أسفل منطقة الأزرار ثم `qamraTouch.markBottom()`.
4. جرّب؛ اضبط العتبة عند الحاجة `qamraTouch.tune({margin: 80})`.

## ١٤. المعمارية العاملة على البوث (2026-10-24)

**اللمس يعمل.** تغيّرات جوهرية عن الخطة الأصلية:

- **لا Web Serial — جسر SSE في الباك-إند.** كروميوم-snap على البوث لا يفتح `/dev/ttyACM0`
  (واجهة `serial-port` بلا slot على Ubuntu الكلاسيكي). الحل: `backend/touch.py` يقرأ المنفذ
  ويبثّ `R,d,v` عبر `GET /api/touch/stream` (SSE)؛ و`touch-serial.js` يستهلكه بـ`EventSource`.
  يُفعّل بـ`MIRROR_TOUCH=1`. pyserial في venv؛ المستخدم في مجموعة `dialout`.
- **وضع Long إلزامي.** Short يفقد اليد عند ~٤٤٥مم (نصف الشاشة الطولية فقط). `single_main.cpp`
  الآن `setDistanceModeLong()` + timing budget 50مل‌ث → يغطّي كامل الارتفاع (~٥٠–١٤٠٠مم).
  المشهد الفارغ في Long يعطي خلفية ~٢٧٠٠مم → بوّابة `maxMm` ترفضها.
- **معايرة على الخادم** (`data/touch_cal.json`، نقاط خطّية بالقطع): `GET/POST /api/touch/cal`،
  تُجلب كل ٣ث فتسري بلا إعادة تحميل. حقول: `points`, `minMm/maxMm`, `pressFrames/releaseFrames/
  cooldownMs`, `calibrate`, `rev`. نسخة احتياطية عاملة: `docs/touch_cal.booth.json`.
- **نقرة ذرّية واحدة** عند التحرّر (نلتقط العنصر مرّة ونرسل pointerdown+pointerup+click دفعةً)
  + هامش تحرّر + تهدئة → لا نقر مزدوج ولا تتالي عبر الشاشات.
- **إعادة تحميل ذاتية:** رفع `rev` يجعل الكيوسك يعيد تحميل نفسه (تحديث JS بلا إقلاع).

### إجراء إعادة المعايرة (لاحقاً / عند تغيّر موضع الحسّاس)
1. من جهاز على الشبكة: `curl -X POST -H "X-Admin-Pin: <PIN>" -H "Content-Type: application/json"
   -d '{"calibrate":true}' http://<booth>:8000/api/touch/cal` (أو من البوث محلياً بلا PIN).
2. على شاشة البوث تظهر ٥ أهداف من الأعلى للأسفل — ضع **كفّاً مفتوحاً** على سطح الشاشة عند كل
   دائرة واثبت أثناء القياس. تُحسب النقاط وتُحفظ تلقائياً وينطفئ العلم.
3. للاستعادة بدل المعايرة: انسخ `docs/touch_cal.booth.json` إلى `data/touch_cal.json` وأعد تشغيل
   `qamra-backend`، أو POST محتوياته إلى `/api/touch/cal`.

### إعادة فلاش الفيرموير عن بُعد (دون نزع العتاد)
ابنِ على الماك `pio run -e esp32-s3`؛ انقل `.pio/build/esp32-s3/firmware.bin` للبوث؛ أوقف
`qamra-backend` (يحرّر المنفذ)؛ `~/mirror/.venv/bin/python -m esptool --chip esp32s3 --port
/dev/ttyACM0 write_flash 0x10000 firmware.bin` (تطبيق فقط)؛ شغّل `qamra-backend`.

> تحذير: `reboot` عن بُعد قد لا يُعيد الإقلاع (بطّارية ميّتة)؛ استخدم إعادة التحميل الذاتية (`rev`)
> بدل الإقلاع لتحديثات الواجهة.
